# 밤낮딜리버리 풀필먼트 주문접수 시스템

셀러가 고객 배송 주문을 등록(단건/엑셀)하고, 밤낮딜리버리 관리자가 모든 주문을 모아 마감·다운로드하는 웹페이지입니다.

| 파일 | 내용 |
|---|---|
| `index.html` | 화면 전체 (HTML + JavaScript 한 파일) |
| `supabase/schema.sql` | DB 테이블·보안 규칙. Supabase SQL Editor에서 실행 |
| `settle-admin.js` | 관리자 > 정산서 발송 탭 기능 |
| `settle.html` | 거래처가 링크로 여는 정산서 화면 (로그인 없음) |
| `supabase/settlement.sql` | 정산서 발송용 테이블. schema.sql 다음에 한 번 실행 |
| `supabase/settlement_versions.sql` | 정산서 회차(1차·2차·3차) 기록. settlement.sql 다음에 한 번 실행 |
| `ship-admin.js` / `ship.html` | 관리자 > 운송장 전송 탭 / 업체가 링크로 여는 운송장 화면 (로그인 없음) |
| `supabase/shipping.sql` | 업체별 운송장 저장 표. 한 번 실행 (여러 번 실행해도 안전) |
| `supabase/signup_notify.sql` | 새 회원가입 알림 문자용. 한 번 실행 (여러 번 실행해도 안전) |
| `stock-admin.js` | 관리자 > 재고관리 탭 기능 |
| `stock.html` | 셀러가 로그인해서 자기 재고를 보는 화면 (`/stock`) |
| `supabase/stock.sql` | 거래처 재고 테이블. schema.sql 다음에 한 번 실행 |

## 접수 시간 안내 (한국 시간 기준)

- 주문 접수는 **24시간 언제나 가능**합니다.
- **07:30 ~ 14:00** 사이에 접수하면, 등록 직후 알림창으로 아래 안내가 뜹니다. (상단 배너도 주황색으로 바뀜)
  > 급하게 당일 출고가 필요한 주문건은 접수누락을 방지하기위해 반드시 카카오톡 단톡방으로 접수 안내 메세지를 보내주셔야합니다.
- 셀러는 **관리자 마감(접수완료) 전 + 출고 전**인 주문만 수정·삭제할 수 있습니다. (DB에서도 강제)

## 주문 번호와 출고 관리

- 주문(상품)마다 **NO.** 가 자동으로 붙습니다.
  - **셀러 화면의 NO.** 는 셀러마다 자기가 접수한 순서대로 **1번부터** 매겨지는 번호입니다(삭제해도 다른 주문 번호는 바뀌지 않음).
    목록은 최신순/오래된순(1번부터)으로 정렬할 수 있습니다.
  - **관리자 화면의 NO.** 는 전체 주문 번호이며, 아래에 `셀러 #3` 처럼 셀러 화면 번호가 함께 표시됩니다.
- 상품명에 **`(합)`** 이 있고 같은 받는분(이름·연락처·주소)이면 한 주문으로 묶여 **`15-1`, `15-2`** 처럼 상품마다 번호가 붙습니다.
  `(합)` 이 없는 상품은 각각 별도 번호를 받습니다(자동 부분출고 대상).
- 관리자 화면 주문마다 **[접수]** 버튼(또는 체크 후 **[선택 접수]**) → `접수완료`. 이때부터 셀러는 수정·삭제할 수 없습니다.
- 주문마다 **택배사** 선택칸과 **송장번호** 입력칸이 있고, 송장번호를 입력한 뒤 **[출고완료]**(또는 Enter)를 누르면 출고완료가 됩니다.
  **송장번호가 없으면 출고완료로 바꿀 수 없습니다**(DB에서도 강제). 출고완료되면 자동으로 접수완료도 됩니다.
- **[송장번호 업로드]**: 엑셀의 **송화인명 + 수화인명 + 주소**가 같은 미출고 주문을 찾아 송장번호를 넣고 출고완료 처리합니다.
  머리글 이름으로 열을 찾습니다(송화인/보내는분, 수화인/받는분/수취인, 주소, 송장/운송장번호, 택배사). 택배사 열이 없으면 옆의 **기본 택배사**를 씁니다.
  합배송(같은 받는분) 상품은 같은 송장번호를 받고, 찾지 못한 행은 목록으로 알려줍니다.
- **[택배사 관리]**: 택배사 목록을 언제든 추가·삭제할 수 있습니다(기본: 우체국택배, 딜리래빗(당일택배)).
- 주문 단위로 **미출고 / 부분출고(1/2) / 출고완료** 가 표시되고, 출고 상태로 필터링할 수 있습니다. 셀러 화면에도 택배사·송장번호가 보입니다.
- **주문 조회**: 셀러 화면과 같은 기간 버튼(오늘/어제/1주일/1개월/1년/전체)·날짜 지정·검색(셀러 가입상호, 송화인, 수취인,
  연락처, 주소, 쇼핑몰상품명, 도매처, 송장번호, 밤낮 메세지)·거래처·구분·출고·**접수상태(접수대기/접수완료)**·정렬.
  기간 버튼은 바로 조회되고, 나머지 조건은 **[조회]** 버튼(또는 검색칸 Enter)을 눌러야 적용됩니다. 엑셀 다운로드도 조회 결과 기준입니다.
- **[선택 접수취소]**: 체크한 [접수완료] 주문을 [접수대기]로 되돌립니다 (셀러가 다시 수정·삭제 가능, 출고완료 상품은 제외).
- **정산서 발송** 탭: 상태(미발송/발송완료/링크 생성됨/발송실패/저장 전)·결과·연락처 유무·상호 검색·정렬로 **[조회]**.
  **[발송완료 전체 체크] / [미발송 전체 체크] / [체크 해제]** 로 조회된 업체를 상태별로 한 번에 체크합니다.
  아무것도 체크하지 않고 [알림톡 발송]을 누르면 지금 조회된 업체 중 아직 안 보낸 곳에만 보냅니다.
- **사입 픽업요청** 탭: 기간·상태·대납·검색 조건으로 [조회], 체크박스로 여러 건 선택 → [선택 항목 상태변경].
  상태는 바꾼 뒤 **[변경 저장]**을 눌러야 저장되고, **[변경 취소]**로 되돌릴 수 있습니다.
- 주문 목록은 별도 박스 안에서 상하·좌우로 스크롤되고 머리줄이 고정됩니다(셀러 화면도 동일).
- **운송장정보** 칸(택배사 선택 + 송장번호)은 송화인과 수화인 사이에 있습니다. 송장번호 입력 후 Enter 를 누르면 바로 출고완료됩니다.
- 상단 **[선택수정]**: 체크한 주문 1건을 수정합니다. (목록 오른쪽 관리 칸은 없앴습니다)
- 주문 목록에 **셀러 가입상호**(회원가입 때 등록한 상호) 열이 있고, 사무실 보관요청이 있는 주문은 밤낮 메모 칸에 `📦 보관요청: 메모` 가 표시됩니다.
- **엑셀 다운로드**는 현재 필터(거래처·구분·출고상태)가 적용된 주문을 아래 8개 시트로 나눠 받습니다.
  1. `풀필먼트 접수건 (풀필)` 2. `일반택배 접수건 (일반)` 3. `당일택배 접수건 (당택)`
     — 2026 풀필먼트 양식(A열 NO. + 기존 13개 열) 그대로이며, 뒤(O열~)에 상품/주문 출고상태, 택배사, 송장번호,
       셀러 가입상호, 접수일시, 처리상태, 사무실 보관요청, 보관요청 메모가 붙습니다.
  4. `사무실 보관 요청건 (킵)` — 보관요청 메모, 접수일·시간, 그날 그 셀러가 접수한 택배 종류(일반택배/당일택배/풀필먼트 ✔)
  5. `셀러별 접수유형` — 예: `(풀필+킵)누보`, `(풀필+일반+당택+킵)누보` (가입상호 기준, 종류별 건수 포함)
  6. `풀필도소매명` — 보내는사람 상호명(송화인 괄호 안), 수취인명, 쇼핑몰상품명, 도매처명, 도매상품명
  7. `킵출고리스트` — 쇼핑몰 상품명에 '킵'이 들어간 풀필먼트 접수건 (6번 열 + 밤낮딜리버리 전달메세지)
  8. `밤낮전달메세지리스트` — 밤낮딜리버리 전달메세지를 적은 풀필먼트 접수건 (7번과 같은 열)
- 셀러 엑셀 업로드는 새 양식(NO. 열 있음)과 예전 양식(NO. 열 없음)을 모두 읽습니다.

## 엑셀 양식

- 셀러가 받는 **엑셀 양식은 밤낮딜리버리 원본 파일 그대로**입니다(1번 `풀필먼트 엑셀양식 작성안내`, 2번 `풀필먼트 엑셀양식`).
  글꼴·색상·열 너비·줄바꿈은 원본과 같고, 2번 시트 3행의 예시 송화인/연락처만 로그인한 셀러 정보로 바뀌어 받아집니다.
- 관리자 다운로드와 셀러의 **조회결과 엑셀**도 같은 원본 파일의 3행부터 주문을 채워서 만듭니다.
- 원본 양식을 바꾸려면 `index.html` 맨 아래 `FULFILLMENT_TEMPLATE_B64` 값을 새 파일의 base64 로 교체하면 됩니다.
  (예: 터미널에서 `base64 -w0 새양식.xlsx`) — 2번 시트의 열 순서(A열 NO. ~ N열 우편번호)는 유지해야 합니다.
- 업로드할 때 송화인 상호가 내 상호와 다른 행이 있으면 한 번 더 확인합니다(예시 '애플샵'을 그대로 둔 경우 등).

## 셀러 화면 기능

- **회원가입 필수 항목**: 상호명·이메일·비밀번호·**대표자명·연락처·매장/사무실 주소**(주소 검색 + 상세주소).
  주소는 셀러 프로필에 저장되어 내정보·관리자 셀러 관리(목록·엑셀·정보수정)에서 보고 고칠 수 있습니다 (`supabase/profile_address.sql`).
- **세금계산서 발행을 위한 정보**(선택 입력, 회원가입 정보 아래 별도 칸): 사업자등록번호·상호(법인명)·대표자명·세금계산서 받을 이메일.
  사업자번호는 끝자리 검증으로 오타를 잡고 `000-00-00000` 으로 맞춰 저장합니다. 내정보·관리자 셀러 관리(목록·검색·엑셀·정보수정)에서 보고 고칠 수 있습니다 (`supabase/profile_tax.sql`).
- **비밀번호 규칙**: 8자 이상 + 숫자 또는 특수문자 1개 이상 (회원가입·내정보 변경·비밀번호 재설정 모두 적용).
- **회원가입·승인 알림 문자** (`worker/notify.js`): 셀러가 가입하면 대표님 휴대폰(`ADMIN_NOTIFY_PHONE`)으로 상호·대표자·연락처 문자가 가고,
  관리자가 승인대기 셀러를 **[승인]**하면 그 셀러 연락처로 "승인되었습니다" 문자가 갑니다(정지해제는 보내지 않음).
  테스트 사이트에서는 승인 문자도 셀러 대신 대표님 휴대폰으로 갑니다. 카카오 알림톡 템플릿 승인 전까지는 문자로 보냅니다.
- **회원가입 상호명 [중복확인]**: 이미 가입된 상호명(띄어쓰기·영문 대소문자 무시)은 쓸 수 없고, [중복확인]을 통과해야 가입됩니다.
  DB 에서도 같은 상호명이 두 번 생기지 않게 막습니다 (`supabase/company_unique.sql`). 관리자가 셀러 상호를 바꿀 때도 같은 규칙이 적용됩니다.

- 로그인하면 택배접수 종류를 크게 둘로 고릅니다(마지막 선택을 기억).
- 접수 종류 카드 오른쪽에 **[픽업건 중 사무실 보관요청]** 박스가 항상 보입니다. 옵션을 고르고 **[접수]** 버튼까지 눌러야 접수됩니다.
  `1. 보관건 있습니다`(메모 필수) → '보관요청' 건으로 내 접수 주문목록·관리자 목록·엑셀 '사무실 보관 요청건' 시트에 올라갑니다.
  `2. 보관건 없습니다` / `3. 이미 접수했습니다` → 확인만 하고 목록에는 올라가지 않습니다.
  로그인할 때마다 보관요청 [접수]를 먼저 해야 택배 접수(매장·풀필먼트 단건/엑셀)를 할 수 있습니다. 보관요청 건은 수정 대신 삭제 후 다시 접수합니다.
- **내 접수 주문목록**은 접수 종류와 상관없이 모든 접수건(우체국·당일·풀필먼트·보관요청)을 함께 보여주며, 처음에는 **오늘** 접수한 내역이 나옵니다.
  기간 버튼은 누르면 바로 조회되고, 날짜·검색어·접수구분·접수상태·출고상태·정렬은 **[조회]** 버튼(또는 검색칸에서 Enter)을 눌러야 적용됩니다.
- 엑셀 일괄 등록은 파일을 **끌어다 놓아도** 바로 접수됩니다(.xlsx/.xls).
- 연락처는 띄어쓰기·점(.)·괄호가 섞여 있어도 자동으로 `010-1234-5678`, `02-123-4567`, `0504-1234-5678`, `1588-1234` 형식으로 맞춰집니다.
- 주문마다 **접수구분**(풀필먼트 / 매장·우체국 / 매장·당일)이 저장되고, 셀러 목록·관리자 화면에서 구분 표시 및 필터가 됩니다.

- **송화인명**: `밤낮딜리버리(상호)` 의 괄호 안 상호가 기본으로 내 상호로 채워지며, 필요하면 주문마다 바꿀 수 있습니다.
  괄호 칸은 기본 3글자 크기이고 상호가 길면 글자 수만큼 늘어납니다.
- **연락처**: `010-1234-5678` 또는 `01012345678` 둘 다 입력 가능하며, 저장할 때 `010-1234-5678` 형식으로 맞춰집니다.
- **자주 쓰는 주소록**: 주문서에 주소를 입력하고 **[+ 지금 입력한 주소 저장]** → 이후 주소 아래 버튼을 한 번 누르면
  받는사람·연락처·주소가 바로 채워집니다. **[주소록]** 버튼에서 검색·선택·삭제.
- **지난 주문 조회**: 오늘 / 어제 / 1주일 / 1개월 / 1년 / 전체 버튼, 날짜 직접 지정, 수취인·연락처·주소·쇼핑몰상품명 검색,
  조회결과 엑셀 다운로드.
- **내정보**: 계정 정보 확인, 대표자명·기본 C/S 연락처 수정, 비밀번호 변경(현재 비밀번호 확인 후).

## 권한 구조

- **셀러**: 본인 주문만 조회·등록·수정·삭제. 상호명(송화인 업체)과 상태(`접수완료`)는 스스로 바꿀 수 없습니다.
  - 가입 직후에는 **승인대기** 상태라 주문할 수 없고, 관리자가 승인해야 주문이 가능합니다.
  - **정지**된 셀러는 기존 주문 조회만 가능합니다.
- **관리자**: 로그인 화면의 **[밤낮딜리버리 관리자]** 탭에서 로그인합니다.
  - **주문 관리** 탭: 모든 주문 조회·수정, 출고 처리(상품별), 마감 처리, 엑셀 다운로드
  - **셀러 관리** 탭: 가입 셀러 목록(상호명·대표자·연락처·이메일·가입일·주문수), 가입 승인/정지/정지해제, 셀러 정보 수정, 셀러 목록 엑셀 다운로드
- 로그인은 Supabase Auth(이메일 + 비밀번호)를 사용하며, 비밀번호는 암호화되어 저장됩니다.

## 처음 설정하기 (Supabase 대시보드)

### 1. DB 스키마 실행
**SQL Editor** → `supabase/schema.sql` 내용 전체 붙여넣기 → **Run**
(여러 번 실행해도 안전합니다. 기존 `orders` 데이터는 유지됩니다.)
`schema.sql`이 바뀔 때마다 다시 실행해주세요. 셀러 승인 기능 추가 전에 이미 가입한 계정은 자동으로 **승인** 상태가 됩니다.
기존 주문에는 접수 순서대로 주문 번호가 채워지고, 출고 상태는 **미출고**로 시작합니다.

### 2. 로그인(Auth) 설정
**Authentication → Sign In / Providers → Email**
- `Enable Email provider`: 켜기
- `Confirm email`: **끄기 권장** — 관리자 승인 제도가 있어 이메일 인증 없이도 승인 전에는 주문할 수 없습니다.
  켜 두면 Supabase 기본 메일 서버의 발송 한도(시간당 약 2통) 때문에 가입 시 "발송 한도 초과" 오류가 납니다. 켜려면 3번 SMTP 연결이 먼저 필요합니다.

**Authentication → URL Configuration** (안 하면 인증 메일 링크가 `localhost`로 가서 "사이트에 연결할 수 없음"이 뜹니다)
- `Site URL`: `https://bamnatconnect.netlify.app`
- `Redirect URLs`: `https://bamnatconnect.netlify.app/**` 추가 (가입 인증·비밀번호 재설정 메일 링크가 이 주소로 돌아옵니다)

### 3. 메일 발송(SMTP) 설정 — 실제 운영 전 필수
Supabase 기본 메일 서버는 **프로젝트 팀원 이메일로만, 시간당 몇 통만** 보냅니다. 셀러에게 가입 인증·비밀번호 재설정 메일이 가려면
**Authentication → Emails → SMTP Settings**에서 외부 메일 서비스(Resend, AWS SES, 네이버 웍스 메일 등)를 연결하세요.
메일 템플릿(한국어 문구)도 같은 메뉴에서 바꿀 수 있습니다.

### 4. 관리자 계정 만들기 (처음 한 번)
1. 사이트의 **[셀러 로그인] 탭 → 회원가입하기**에서 관리자가 쓸 이메일로 가입 (상호명은 `밤낮딜리버리` 등 아무거나)
2. SQL Editor에서 실행 (이메일 부분만 바꾸기):
   ```sql
   update public.profiles set role = 'admin', status = 'approved'
   where id = (select id from auth.users where email = '관리자이메일@example.com');
   ```
3. 사이트의 **[밤낮딜리버리 관리자] 탭**에서 그 이메일로 로그인하면 관리자 화면이 열립니다.

관리자 권한 부여/회수는 보안을 위해 SQL로만 할 수 있습니다. (관리자 화면에서도 바꿀 수 없음)

### 5. 예전 방식 셀러 정리
예전 `sellers` 테이블(비밀번호가 평문 저장)은 1번 스키마 실행으로 앱에서 더 이상 읽을 수 없게 막혔습니다.
기존 셀러들은 **이메일로 새로 회원가입**해야 하며, 모두 옮겨온 뒤 `schema.sql` 5번 항목의 `drop table` 줄을 실행해 삭제하세요.
예전 주문(`seller_id`가 비어 있는 주문)은 관리자에게만 보입니다.

> 아래 링크·발송 기능까지 쓰려면 `SHIP_FULL_FEATURES` 를 `true` 로 바꿉니다.

- 주문마다 송장번호를 입력하던 칸(관리자)과 운송장정보·출고 표시(셀러)는 숨겼습니다 (`index.html` 의 `SHOW_SHIPPING_UI = false`).
- 관리자 **[운송장 전송]** 탭: 송장 엑셀(송화인 · 수화인명 · 운송장번호 · 상품명 · 부피추가비용)을 올리면
  - 송화인 `밤낮딜리버리(상호)` 의 괄호 안 상호로 업체를 나눕니다. **지금은 괄호가 있는 줄만 받고**, 송화인이 그냥 `밤낮딜리버리`(매장·사무실 발송)인 줄은 넣지 않습니다 (`SHIP_ONLY_BRACKETED = true`). 업체 순서는 엑셀에 처음 나온 순서입니다. 송화인이 그냥 `밤낮딜리버리` 면 매장으로 보내는 건이라 수화인을 업체로 봅니다
    (`유어피치(눈타이드)` 처럼 괄호가 있으면 연락처·회원·엑셀에 있는 상호 쪽으로).
  - **송장 작업표 v6 형식**도 됩니다: `출력송장` 시트(송장번호가 다 적힌 원본) + `미출고송장` 시트(미출고 송장번호 목록)를 올리면, 목록에 있는 송장은 미출고로 봅니다. `…결과값` 시트는 읽지 않습니다.
  - 운송장번호 칸: 번호 → 출고, `번호/부출` → 부분출고, `미출고` → 미출고. **출고건수 = 서로 다른 송장번호 개수** (합포장은 1건).
  - [저장]하면 업체마다 확인 링크(`/ship?t=...`)가 생깁니다. 같은 날 다시 올리면 바뀐 업체만 다시 저장되고, 보낸 뒤 바뀌면 '수정됨·미발송'.
  - **체크한 업체만** [선택 업체 발송] → "○○님, M월 D일 운송장정보가 전달되었습니다. 출고건수: N건 (미출고 k개 상품)" + 링크.
    연락처는 정산서 탭 거래처 연락처 → 없으면 회원가입 연락처. 테스트 사이트에서는 [시험 발송 (내 번호)]만 됩니다.
  - 단톡방은 카카오 정책상 자동 발송이 안 되어, [단톡방용 문구 복사]로 붙여넣습니다.
- 지금은 **문자**로 보냅니다. 카카오 알림톡 템플릿이 승인되면 Cloudflare 설정에 `SOLAPI_SHIP_TEMPLATE_ID` 를 넣으면 알림톡으로 바뀝니다.
  템플릿 문구(솔라피에 등록, 변수 이름 그대로):
  ```
  [밤낮딜리버리 운송장 안내]
  #{상호}님, #{출고일} 운송장정보가 전달되었습니다.

  ■ 출고건수: #{출고건수}건
  #{미출고안내}

  아래 버튼에서 받는분별 운송장번호를 확인해 주세요.
  ```
  버튼: 웹링크 "운송장 확인" → `https://bamnat-delivery.bamnat.workers.dev/ship?t=#{토큰}`
