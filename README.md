# 밤낮딜리버리 풀필먼트 주문접수 시스템

셀러가 고객 배송 주문을 등록(단건/엑셀)하고, 밤낮딜리버리 관리자가 모든 주문을 모아 마감·다운로드하는 웹페이지입니다.

| 파일 | 내용 |
|---|---|
| `index.html` | 화면 전체 (HTML + JavaScript 한 파일) |
| `supabase/schema.sql` | DB 테이블·보안 규칙. Supabase SQL Editor에서 실행 |

## 접수 시간 안내 (한국 시간 기준)

- 주문 접수는 **24시간 언제나 가능**합니다.
- **07:30 ~ 14:00** 사이에 접수하면, 등록 직후 알림창으로 아래 안내가 뜹니다. (상단 배너도 주황색으로 바뀜)
  > 급하게 당일 출고가 필요한 주문건은 접수누락을 방지하기위해 반드시 카카오톡 단톡방으로 접수 안내 메세지를 보내주셔야합니다.
- 셀러는 **관리자 마감(접수완료) 전 + 출고 전**인 주문만 수정·삭제할 수 있습니다. (DB에서도 강제)

## 주문 번호와 출고 관리

- 주문(상품)마다 **NO.** 가 자동으로 붙습니다.
  - **셀러 화면의 NO.** 는 셀러마다 자기가 접수한 순서대로 **1번부터** 매겨지는 번호입니다(삭제해도 다른 주문 번호는 바뀌지 않음).
    목록은 최신순/오래된순(1번부터)으로 정렬할 수 있습니다.
  - **관리자 화면의 NO.** 는 전체 주문 번호이며, 아래에 `셀러 #3` 처럼 셀러 화면 번호가 함께 표시됩니다.
- 상품명에 **`(합)`** 이 있고 같은 받는분(이름·연락처·주소)이면 한 주문으로 묶여 **`15-1`, `15-2`** 처럼 상품마다 번호가 붙습니다.
  `(합)` 이 없는 상품은 각각 별도 번호를 받습니다(자동 부분출고 대상).
- 관리자 화면 주문마다 **[접수]** 버튼(또는 체크 후 **[선택 접수]**) → `접수완료`. 이때부터 셀러는 수정·삭제할 수 없습니다.
- 주문마다 **택배사** 선택칸과 **송장번호** 입력칸이 있고, 송장번호를 입력한 뒤 **[출고완료]**(또는 Enter)를 누르면 출고완료가 됩니다.
  **송장번호가 없으면 출고완료로 바꿀 수 없습니다**(DB에서도 강제). 출고완료되면 자동으로 접수완료도 됩니다.
- **[송장번호 업로드]**: 엑셀의 **송화인명 + 수화인명 + 주소**가 같은 미출고 주문을 찾아 송장번호를 넣고 출고완료 처리합니다.
  머리글 이름으로 열을 찾습니다(송화인/보내는분, 수화인/받는분/수취인, 주소, 송장/운송장번호, 택배사). 택배사 열이 없으면 옆의 **기본 택배사**를 씁니다.
  합배송(같은 받는분) 상품은 같은 송장번호를 받고, 찾지 못한 행은 목록으로 알려줍니다.
- **[택배사 관리]**: 택배사 목록을 언제든 추가·삭제할 수 있습니다(기본: 우체국택배, 딜리래빗(당일택배)).
- 주문 단위로 **미출고 / 부분출고(1/2) / 출고완료** 가 표시되고, 출고 상태로 필터링할 수 있습니다. 셀러 화면에도 택배사·송장번호가 보입니다.
- **엑셀 다운로드**는 2026 풀필먼트 양식(A열 NO. + 기존 13개 열) 그대로 받아지며, 현재 필터(거래처·출고상태)가 적용됩니다.
  양식 뒤(O열~)에 관리자용으로 상품/주문 출고상태, 거래처, 접수일시, 처리상태가 붙습니다.
- 셀러 엑셀 업로드는 새 양식(NO. 열 있음)과 예전 양식(NO. 열 없음)을 모두 읽습니다.

## 엑셀 양식

- 셀러가 받는 **엑셀 양식은 밤낮딜리버리 원본 파일 그대로**입니다(1번 `풀필먼트 엑셀양식 작성안내`, 2번 `풀필먼트 엑셀양식`).
  글꼴·색상·열 너비·줄바꿈은 원본과 같고, 2번 시트 3행의 예시 송화인/연락처만 로그인한 셀러 정보로 바뀌어 받아집니다.
- 관리자 다운로드와 셀러의 **조회결과 엑셀**도 같은 원본 파일의 3행부터 주문을 채워서 만듭니다.
- 원본 양식을 바꾸려면 `index.html` 맨 아래 `FULFILLMENT_TEMPLATE_B64` 값을 새 파일의 base64 로 교체하면 됩니다.
  (예: 터미널에서 `base64 -w0 새양식.xlsx`) — 2번 시트의 열 순서(A열 NO. ~ N열 우편번호)는 유지해야 합니다.
- 업로드할 때 송화인 상호가 내 상호와 다른 행이 있으면 한 번 더 확인합니다(예시 '애플샵'을 그대로 둔 경우 등).

## 셀러 화면 기능

- 로그인하면 택배접수 종류를 크게 둘로 고릅니다(마지막 선택을 기억).
  - **🏬 매장/사무실 택배접수 (사입대행택배)** → **📮 우체국택배 접수** / **🚚 당일택배 접수** 중 선택
    (당일택배 옆 **[가능지역 조회]** 는 딜리버스 조회 페이지를 새 창으로 엽니다)
    - 송화인명 `밤낮딜리버리`, 보내는사람 연락처 `010-5425-9060` 고정
    - 수화인명은 기본으로 내 상호, 받는사람 연락처는 내 연락처가 채워짐(수정 가능)
    - 받을 주소(매장/사무실) 필수, 상품명 생략 가능, 배송메세지·밤낮 전달메세지 선택, 도매 칸 없음
    - **[최근 접수내용 재등록]**: 같은 종류(우체국/당일)로 마지막에 접수한 내용을 그대로 채워서 [주문 등록하기]만 누르면 됨
  - **📦 고객풀필먼트 택배접수 (고객배송대행)** → 기존 단건/엑셀 일괄 접수
- 주문마다 **접수구분**(풀필먼트 / 매장·우체국 / 매장·당일)이 저장되고, 셀러 목록·관리자 화면에서 구분 표시 및 필터가 됩니다.

- **송화인명**: `밤낮딜리버리(상호)` 의 괄호 안 상호가 기본으로 내 상호로 채워지며, 필요하면 주문마다 바꿀 수 있습니다.
  괄호 칸은 기본 3글자 크기이고 상호가 길면 글자 수만큼 늘어납니다.
- **연락처**: `010-1234-5678` 또는 `01012345678` 둘 다 입력 가능하며, 저장할 때 `010-1234-5678` 형식으로 맞춰집니다.
- **자주 쓰는 주소록**: 주문서에 주소를 입력하고 **[+ 지금 입력한 주소 저장]** → 이후 주소 아래 버튼을 한 번 누르면
  받는사람·연락처·주소가 바로 채워집니다. **[주소록]** 버튼에서 검색·선택·삭제.
- **지난 주문 조회**: 오늘 / 어제 / 1주일 / 1개월 / 1년 / 전체 버튼, 날짜 직접 지정, 수취인·연락처·주소·쇼핑몰상품명 검색,
  조회결과 엑셀 다운로드.
- **내정보**: 계정 정보 확인, 대표자명·기본 C/S 연락처 수정, 비밀번호 변경(현재 비밀번호 확인 후).

## 권한 구조

- **셀러**: 본인 주문만 조회·등록·수정·삭제. 상호명(송화인 업체)과 상태(`접수완료`)는 스스로 바꿀 수 없습니다.
  - 가입 직후에는 **승인대기** 상태라 주문할 수 없고, 관리자가 승인해야 주문이 가능합니다.
  - **정지**된 셀러는 기존 주문 조회만 가능합니다.
- **관리자**: 로그인 화면의 **[밤낮딜리버리 관리자]** 탭에서 로그인합니다.
  - **주문 관리** 탭: 모든 주문 조회·수정, 출고 처리(상품별), 마감 처리, 엑셀 다운로드
  - **셀러 관리** 탭: 가입 셀러 목록(상호명·대표자·연락처·이메일·가입일·주문수), 가입 승인/정지/정지해제, 셀러 정보 수정, 셀러 목록 엑셀 다운로드
- 로그인은 Supabase Auth(이메일 + 비밀번호)를 사용하며, 비밀번호는 암호화되어 저장됩니다.

## 처음 설정하기 (Supabase 대시보드)

### 1. DB 스키마 실행
**SQL Editor** → `supabase/schema.sql` 내용 전체 붙여넣기 → **Run**
(여러 번 실행해도 안전합니다. 기존 `orders` 데이터는 유지됩니다.)
`schema.sql`이 바뀔 때마다 다시 실행해주세요. 셀러 승인 기능 추가 전에 이미 가입한 계정은 자동으로 **승인** 상태가 됩니다.
기존 주문에는 접수 순서대로 주문 번호가 채워지고, 출고 상태는 **미출고**로 시작합니다.

### 2. 로그인(Auth) 설정
**Authentication → Sign In / Providers → Email**
- `Enable Email provider`: 켜기
- `Confirm email`: **끄기 권장** — 관리자 승인 제도가 있어 이메일 인증 없이도 승인 전에는 주문할 수 없습니다.
  켜 두면 Supabase 기본 메일 서버의 발송 한도(시간당 약 2통) 때문에 가입 시 "발송 한도 초과" 오류가 납니다. 켜려면 3번 SMTP 연결이 먼저 필요합니다.

**Authentication → URL Configuration** (안 하면 인증 메일 링크가 `localhost`로 가서 "사이트에 연결할 수 없음"이 뜹니다)
- `Site URL`: `https://bamnatconnect.netlify.app`
- `Redirect URLs`: `https://bamnatconnect.netlify.app/**` 추가 (가입 인증·비밀번호 재설정 메일 링크가 이 주소로 돌아옵니다)

### 3. 메일 발송(SMTP) 설정 — 실제 운영 전 필수
Supabase 기본 메일 서버는 **프로젝트 팀원 이메일로만, 시간당 몇 통만** 보냅니다. 셀러에게 가입 인증·비밀번호 재설정 메일이 가려면
**Authentication → Emails → SMTP Settings**에서 외부 메일 서비스(Resend, AWS SES, 네이버 웍스 메일 등)를 연결하세요.
메일 템플릿(한국어 문구)도 같은 메뉴에서 바꿀 수 있습니다.

### 4. 관리자 계정 만들기 (처음 한 번)
1. 사이트의 **[셀러 로그인] 탭 → 회원가입하기**에서 관리자가 쓸 이메일로 가입 (상호명은 `밤낮딜리버리` 등 아무거나)
2. SQL Editor에서 실행 (이메일 부분만 바꾸기):
   ```sql
   update public.profiles set role = 'admin', status = 'approved'
   where id = (select id from auth.users where email = '관리자이메일@example.com');
   ```
3. 사이트의 **[밤낮딜리버리 관리자] 탭**에서 그 이메일로 로그인하면 관리자 화면이 열립니다.

관리자 권한 부여/회수는 보안을 위해 SQL로만 할 수 있습니다. (관리자 화면에서도 바꿀 수 없음)

### 5. 예전 방식 셀러 정리
예전 `sellers` 테이블(비밀번호가 평문 저장)은 1번 스키마 실행으로 앱에서 더 이상 읽을 수 없게 막혔습니다.
기존 셀러들은 **이메일로 새로 회원가입**해야 하며, 모두 옮겨온 뒤 `schema.sql` 5번 항목의 `drop table` 줄을 실행해 삭제하세요.
예전 주문(`seller_id`가 비어 있는 주문)은 관리자에게만 보입니다.
